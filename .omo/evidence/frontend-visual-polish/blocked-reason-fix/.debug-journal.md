## Root cause (confirmed 2026-09-14)
- Mechanism: typed move entry leaves an INPUT focused, which the window-level key handler intentionally ignores. After focusing a valid history control, ArrowLeft reaches `navPrev()`, but the route effect treated every non-Study `reviewPly` update as if the user had just left Study and called `resumeGame()`, producing a transient history state followed by live state. A synchronous placement read could additionally observe the previous React render.
- Evidence: `runtime-probe.log`, `post-key-state-probe.log`, and `a11y-10-runs.log`.
- Toggle proof: INPUT target produced no browse state; focusing Previous move produced a browse state; with the existing non-Study effect it reverted to live, establishing both mechanisms independently.
- Fix scope: `web/src/workspace/ChessWorkspaceLayout.tsx` route-transition guard and `web/tests/a11y.spec.ts` focus/precondition/web-first assertions.
