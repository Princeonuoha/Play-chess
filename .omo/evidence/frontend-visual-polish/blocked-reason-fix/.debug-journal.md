### 2026-09-14 — browser runtime probe at the history transition
- Source: `runtime-probe.log`; Playwright CDP `getEventListeners(window)` and DOM state immediately before key presses.
- Value: `HISTORY_DEBUG thinking { active: 'INPUT', previousPresent: false, blocked: 'Stockfish is thinking.' }`
- Interpretation: while the controller cannot browse, the product does not expose the Previous move control; the UI browse signal does not lead `canBrowse`.
- Refutes/Confirms: refutes H3.

- Source: `runtime-probe.log`; CDP listener inventory.
- Value: `HISTORY_DEBUG keydown-listeners ["Z=>{const at=Z.target;at instanceof HTMLElement&&[\"INPUT\",\"SELECT\",\"TEXTAREA\"].includes(at.tagName)||(Z.key===\"ArrowLeft\"?g.navPrev():Z.key===\"ArrowRight\"?g.navNext():Z.key===\"Home\"?g.navFirst():Z.key===\"End\"&&g.navLast())}"]`
- Interpretation: history keys are owned by a `window` keydown listener, not the h1 or another scoped element; it intentionally ignores events targeting inputs.
- Refutes/Confirms: refutes H2 and confirms the input-target branch of H1.

- Source: `runtime-probe.log`; DOM state after Previous move appeared and before the original ArrowLeft.
- Value: `HISTORY_DEBUG browsable { active: 'INPUT', previousPresent: true, previousDisabled: false, blocked: 'It is not your move.' }`
- Interpretation: the controller/UI browse precondition is true, but the move-entry input retained focus from `playTyped`.
- Refutes/Confirms: confirms H1; refutes a post-engine `canBrowse` timing race.

- Source: `runtime-probe.log`; two ArrowLeft presses with only focus changed.
- Value: `HISTORY_DEBUG input-target-result It is not your move.` followed by `HISTORY_DEBUG focused-control <button ... aria-label="Previous move" ...>` and a passing browse assertion.
- Interpretation: toggling only the target from INPUT to the enabled Previous move button toggles the keyboard behavior from ignored to successful. Root cause confirmed.
- Refutes/Confirms: confirms H1.
